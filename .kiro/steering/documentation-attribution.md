# Documentation Attribution Rule

## Creator Attribution

All documentation, summaries, README files, and project documentation MUST be attributed to:

**Creator:** Herman Swanepoel

## Attribution Format

### For Markdown Documents
Add the following attribution block at the end of documentation files:

```markdown
---

**Project Creator:** Herman Swanepoel  
**Document Version:** [version]  
**Last Updated:** [date]
```

### For Code Comments
```
// Project Creator: Herman Swanepoel
// [Additional context]
```

### For README Files
Include in the header or footer:
```markdown
## Author

**Herman Swanepoel** - *Project Creator*
```

## Scope

This rule applies to:
- README.md files
- Documentation files (*.md)
- API documentation
- Architecture documents
- User guides
- Developer guides
- Spec documents (requirements.md, design.md, tasks.md)
- Project summaries
- Changelog files
- Contributing guides

## Implementation

When creating or updating any documentation:
1. Always include Herman Swanepoel as the project creator
2. Use consistent attribution format
3. Include version and date information
4. Maintain attribution across all project documentation
